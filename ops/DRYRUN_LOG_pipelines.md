## 3. Activator act_delivery_risk_alerts - CREATED via REST, but NOT confirmed to fire (needs a browser session)

What worked:
- `POST /v1/workspaces/{ws}/reflexes` with `definition.parts=[{"path":"ReflexEntities.json",...}]` (do NOT send `"format":"json"` - `InvalidDefinitionFormat`). The body is generated by `ops/pipelines_rest/make_reflex.py`. Validation is strict and error messages are useful. Facts learned:
  - Rule templates: `AttributeTrigger` with steps ScalarSelectStep (AttributeSelector) -> ScalarDetectStep (`NumberBecomes`, op must be `BecomesGreaterThan`; `BecomesGreaterThanOrEqual` -> 500) + `OccurrenceOption EachTime` -> optional DimensionalFilterStep (`NumberValueCondition` with args `op`=`IsGreaterThanOrEqualTo` and `threshold`, NOT `value`) -> ActStep.
  - Fabric-item action: row kind `FabricItemInvocation` with required args `fabricJobConnectionDocumentId` (uniqueIdentifier of the `fabricItemAction-v1` entity), `workspaceId`, `itemId`, `jobType`, `itemType`, `additionalInformation` (array). I found NO documented/accepted way to map the three pipeline parameters (order_id/late_risk/order_value) - pipeline gets its defaults unless set in the UI.
  - Failed display names stay reserved a few minutes (`ItemDisplayNameNotAvailableYet`).
  - `>= 0.7` has no "becomes >=" op: built as `BecomesGreaterThan 0.7` and `order_value >= 200` as filter.
- The eventstream needs an Activator destination: updated `es_checkout_events` with `{"name":"to-act-delivery-risk","type":"Activator","properties":{"workspaceId":..,"itemId":<reflex id>,"inputSerialization":{"type":"Json","properties":{"encoding":"UTF8"}}},"inputNodes":[{"name":"es_checkout_events-stream"}]}` (status Running). Fabric then adds its own `EventStream` source + `es_checkout_events-stream` event view to the Reflex (visible in getDefinition). NOTE: a wrong itemId (typo) was accepted by the eventstream and reported Running - always check the id.
- IMPORTANT side effect: **any `updateDefinition` on the eventstream replaces the custom endpoint source (new source id, NEW connection string/key)**. The old `app/checkout-simulator/.env` EVENTSTREAM_CONNECTION_STRING/ENTITY_NAME then fail with `CBS Token authentication failed`. Get the new ones with `GET .../eventstreams/{id}/topology` (sources[0].id) then `GET .../sources/{sid}/connection` (`eventHubName`, `accessKeys.primaryConnectionString`); `ops/pipelines_rest/sim.sh N seed` does this. The `.env` file was NOT edited (not mine) - update it before the next app test.
